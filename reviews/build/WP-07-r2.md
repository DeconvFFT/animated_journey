## 3. Tests of my own, designed to break it

All against a local stand-in release server from `tests/sp1/make_fake_release.py` with the fake 2,000 MB `df`, in a scratch folder of my own that I removed afterwards (server stopped). The stand-ins prove the harness mechanics only, nothing about FilmCraft or EffectCraft.

1. **Three `--only effectcraft v0.11.1 --t1-only` runs in a row.** Every run after the first fetched again and recorded the automatic exception; `--ledger-check` exit 0 with 3 fetches of one asset. The console says "the second fetch" for the third one too. So the rule "each tarball once; a second fetch needs a recorded exception" is now self-justifying: nothing in the runner can ever make `--ledger-check` fail except hand-seeded lines or the 2 GB allowance. Not a hazard for the fortnight (one tarball is 64 to 70 MB, and `run_tests.sh` no longer re-fetches), but the ledger's teeth are gone: nudge 1.
2. **`--all --profile full` twice.** Run 2: FilmCraft re-verified and reused the kept tarball ("no second download", "stays where it is for WP-10"); EffectCraft fetched again with the exception `re-fetch: the earlier copy (stage effectcraft-v0.11.1) was deleted with its tree` (no "t1-only", correctly, because run 1 was a full stage); ledger 3 lines, `--ledger-check` clean, `vendor/craft` holds only `_keep/`, the verdict written to `LJ_SP1_VERDICT`, exit 0 both times. Right; this is the real run's own shape (kept FilmCraft, re-fetched EffectCraft).
3. **A timed-out stage as the verdict sees it** (`SP1_STAGE_TIMEOUT_S=4`, through `lj_with_disk` and `timeout`): exit 3, folders removed, envelope `BLOCKED / exit 3: TIMEOUT: the stage ran over 4 s and was stopped; T2's partial envelope holds what was measured`; `verdict.py --print` lists it under "Why they have not run" and in the disk section with the same words. Right.
4. **A table with no `usable` key at all** (`jq 'del(.usable)'`): the stage dies at line 139 with exit 1 and the STOP AND REPORT line, before the preflight HEAD; 0 ledger lines; nothing in the vendor folder. Conservative and right.
5. **The df flag when the kept tarball pre-exists.** `finalize_stage.py` computes `df_back_within_10mb_of_start_plus_kept = abs(delta - kept_mb) <= 10` with `kept_mb` the size of everything in `_keep/`. With a 70 MB file already in `_keep/` and `--df-before 1118 --df-after 1116` (a reuse: nothing new kept) the flag is **false** (`df_delta_mb 2, kept_mb 66.5`). The real `--all`'s FilmCraft stage is exactly this case, so its envelope will carry `false` although the disk came back. The raw figures beside it tell the truth, so it is a misleading boolean, not a wrong measurement: nudge 2. (The real T1 stage, where the tarball was kept during the stage, reads `true`, as it should.)

No scratch path, user or host appears in any envelope written by these runs (the console shows my scratch folder only because the vendor override lies outside the repo; the real runner prints repo-relative paths).
