## 2. Tests of my own designed to break it

1. **Five junk bytes appended to a good venue file.** `spec_check.py` exit 1, `container.atoms` only, detail `5 stray byte(s) at the end`. Nothing else trips; ffprobe and the decoder are both happy with such a file, so this is the only check that would have found it.
2. **A name planted in metadata (built from fragments at run time).** A stream-level `comment` is dropped by the MP4 muxer itself (ffprobe shows only `language`, `handler_name`, `vendor_id`), so the file correctly passes. A format-level `comment` written with `use_metadata_tags` fails `metadata.neutral`, and the console and the verdict JSON show `comment=sc********`: the planted name appears nowhere in stdout, stderr or the JSON.
3. **24000/1001 fps under the venue profile.** exit 1, `video.fps` with `r=24000/1001 avg=24000/1001`; a learner can see what is wrong from the line.
4. **Path leak on a half-readable file in a folder named like a user's photo folder.** The first 20 KB of a faststart venue file: ffprobe opens it, `container.atoms` and `integrity.decode` fail, and the folder name occurs zero times in stdout plus JSON.
5. **`mo8_gate.py` with two inputs, the second 130 frames long.** Refused in 0.14 s before any frame of the first input was loaded: the "check every input first" rule works.
6. **A chain file whose only chain is BT.601 under BT.709 tags and marked `approved: true`.** `colour_patch.py` exit 1, `worst 23/255`, `RESULT approvals: NOT ALLOWED ... sneaky_601`. The derived form of that raw record still says `pass: false`, so a lie in the chain file cannot be laundered through `--derive-from`.
7. **Derive from a raw record with an upper-case SHA-256 and a git-snapshot version (`N-118000-g1a2b3c4d5-20260901`).** Accepted, lower-cased, reduced to `N-118000-g1a2b3c4d5`; the schema mirror agrees.
8. **A frame folder whose files end in `.PNG`.** Refused with `no .png frames in that folder` on Linux. Windows globbing is case-insensitive so the PC is unaffected; on the container this is a clear message, but it is a trip wire for a folder copied over from the PC (nudge 3).

## 3. Findings by rubric

**Correctness (5).** All acceptance lines reproduce: the oracle to the digit, the ten named defects each exit 1 naming their check (ten of them isolated to exactly the named set), the BT.601-under-709 file exits 0 as the plan's oracle requires (D-2 is the right reading: the plan's own parenthesis says "tags pass, colour-patch fails", and the cross test shows luma 81 against 63), nine good files over six profiles exit 0, the MO8 pair separates by a factor of about 100 against the gates, refusals at 97/121/130/6 frames and at `--max-frames 200`. The frame-count check uses `round(duration x fps)` via floor(x + 0.5), `r_frame_rate` and `avg_frame_rate` are both held to 24/1, ebur128 is read from the final `Summary:` block only, atoms are walked with 64-bit sizes and the `size 0 = to end` case, and faststart is judged by atom order rather than a flag. The patch reading as a rounded mean of a 200 x 200 block (D-6) is appropriate for flat patches and the max single-pixel error is recorded beside it.

**Safety and privacy (5).** Redaction by design, not by scrubbing afterwards: base names only, tag values masked to two characters, the file's path replaced in ffmpeg messages, the raw record carries no binary path, the derived writer is built from a fixed field list and validates against a hand-coded mirror of the schema before writing, chain names must be plain identifiers, `public_lint.py` refuses `colour_patch_pc*.json`, the test's planted path-and-name raw record is proven detectable by the lint before the derive test counts. All test material is three flat patches, a sine tone and a generated grey chart; no family media exists, is fetched or is simulated. No Windows script is part of this package; the Python tools are read-only apart from the one `--json` / `--out` file and a temporary folder they delete. Filing the container's raw record (D-7) is correct: the plan's acceptance line names that path, the build is the public Ubuntu package, and the lint is clean on it. Nothing here could tip off the mother.

**Maker usability (4).** `pipeline/validators/README.md` is a real one-page guide: the three questions the three tools answer, the exit codes, the commands for Linux and the PC, the raw-versus-filed rule in a box, the profile shape, what is UNVERIFIED. Each tool prints what it does first and every failure names a check id with "want / got" and, where there is a remedy, the remedy. Two small things: the `.PNG` message above, and `settings.json`'s captions row cites W-16 and W-21 but not W-18 (the captions decision itself), which a maker reading the card and the mirror side by side will trip over.

**Fidelity to the plan and DECISIONS.md (4).** All six deliverables exist in their owner paths with the 4.5 and 4.6 shapes (additive keys only, D-4, read by nothing that would break); the chains are the Q-F1 lines with the W-17 and W-19 numbers; `signed: false`; 24 fps, -1 dBTP, 48 kHz 24-bit, ProRes 422 HQ, the three venue loudness candidates; MO8 gates 0.05 / 0.04 with roughness informational, on the master before the encode (W-41); `mo8_audit.py` reused in place with `python3 -I -B` and unmodified; `--profiles-file` and `--chain-file` take WP-08's shape. D-3 (`expect.profile` null, profile in `expect_extra`) is a sound reading of what `render.mjs` actually compares and is documented in the file itself. The one point short of 5: the filed evidence shows the disk stage SKIPPED (D-1) although the mechanism works and the guard admits it at today's Avail; the report's headline numbers describe the unguarded run. A re-run of `make_evidence.sh` closes it.

**Maintainability (4).** Three tools of about 250 to 730 lines each with a complete header comment, named constants, small functions, no third-party module (checked by AST and by `python -I -S`), fixtures regenerated at test time under a git-ignored folder, `ab_push_card.py` and `mo8_audit.py` reused rather than copied, the Q-F1 numbers and the F-12 table held in one place each.
