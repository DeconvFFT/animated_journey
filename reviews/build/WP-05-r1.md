## Critical issue

**`colour_patch.py` cannot measure a chain whose output is not 1920x1080, and reports the failure as "ABOVE TOLERANCE".** `pipeline/validators/colour_patch.py` `decode_first_frame()` (line 319) rejects any decode that is not `W*H*channels` bytes, so WP-08's `phone_720_share` chain (vf `scale=1280:720:...`, PH2 per W-63 / D-27) comes back `ERROR`, and `run_test()` (line 498) folds that into `chains_fail` and prints it as above tolerance. W-16 requires the colour-patch test "on every command-line template on each ffmpeg build"; the plan's §4.5 says `--chain-file` "can test any file of this shape"; WP-08 depends on WP-05 for exactly this. Fix (small): decode with `DECODE_VF + ",scale=%d:%d:flags=neighbor" % (W, H)` (nearest-neighbour on flat patches is exact), or read the decoded size from ffprobe and scale the patch boxes; and in `run_test()` keep a separate `chains_error` list so the RESULT line says "could not be measured (encode/decode error)" while still exiting 1. Add `phone_720_share`-shaped control (a chain with `scale=1280:720` in `vf`) to `tests/validators/run_checks.py` `t_phone_chain` so the stand-in covers both phone chains.
