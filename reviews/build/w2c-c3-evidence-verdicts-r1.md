1. **The other Whisper environment.** `whisperenv_dir` (2.1 GB; `whisperenv_dir/venv` is a Python 3.13.16 venv with `openai-whisper` 20250625 and `torch` 2.14.1+cpu; `pip_whisper.log` ends `rc=0`) is still in the session scratchpad and is the "Whisper environment of 2.1 GB" that the disk-decision prose and `w2-housekeeping-r1.md` name. 2. **The READY line.** When the ledger already holds a fetch and `SP3_FETCH_REASON` is unset, `run_sp3.sh --check` still ends "READY ... Start it with: bash spikes/sp3_blender/run_sp3.sh --run", and that command then exits 3. Add to the READY line, in that case, "(2 fetches on the ledger: `--run` needs `SP3_FETCH_REASON='why'`)". One `say` and one test.
3. **A failed install is still a fetch.** The ledger row is appended only after `pip install` succeeds. A `--require-hashes` install that downloads 400 MB and then stops on a mismatched or withdrawn file has fetched bytes the allowance never sees. Either append a row with a `note` "install failed after download" on the failure path, or write in `README.md` and `ledger_row.py` that a failed attempt is recorded by hand with `append --note`.
4. **`assemble.py import` ambiguity.** A "does not say" bullet that names two spikes is given to the first match in the fixed order (SP4, SP3, SP1, SP2, SP5). Refuse an ambiguous bullet with exit 2 and a message, or say in the README that such a bullet must be split before an import. Recovery tool only, so low priority.
5. **The allowance figure.** Section 2.2 says a third fetch "fits with about 130 MB to spare"; in the integration test's own units (bytes over 1e6 against 2,048 MiB) it is nearer 25 MB. State both numbers in the SP3 row's next-step cell, or none, so the orchestrator decides the G1 fetch on the tighter one.
