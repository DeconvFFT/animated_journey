## 2. Tests of my own, designed to break it

1. **The real Windows layout for the runner (the one that matters).** On the PC `%TEMP%` is `C:\Users\<name>\AppData\Local\Temp`, so if `spec_check.py` or `colour_patch.py` printed the clip or chain-file path, `run_checks_pc.ps1` would refuse its own clean output on every PC. I ran the real flow with `TEMP` under `<scratch>/Users/<invented>/AppData/Local/Temp` and `USERNAME=<invented>`: exit 0, `ok (nothing matched)`, raw file written, temporary folder gone. `spec_check` prints the base name only; `colour_patch` prints no path. Good: no false refusal, no leak.
2. **Archive files re-saved by the maker's editors.** `checksums.txt` with a BOM and CRLF (Notepad): verification still right (only the planted mismatch). `manifest.csv` with a quoted, CRLF header (Excel): accepted as the playbook header. Good.
3. **Ken Burns tool, failing output paths.** `--out <an existing file>/x.mp4`: an unhandled `FileExistsError` prints a raw Python traceback with the absolute path of `kenburns_24.py` and the output path, exit 1. A forced ffmpeg output-open failure (a folder sitting where `x.mp4.part.mp4` goes): `environment problem: ffmpeg stopped early ... Error opening output <full output path>`, exit 3. Both print paths that on the PC would read `C:\Users\<name>\...` whenever the project or the output sits under the profile (the default output is inside the project folder). See section 3.
4. **A still that is not an image, `/proc/self` as output (0 MB free), unwritable folders**: refused cleanly with exit 2 or 3 and no path. `pc_helpers.py` has the same two gaps as item 3 (`merge-chains` traceback on a missing folder; `clip` tail with the full output path), but the runner passes both through `Clean-Message`, so they are not reachable from the maker's flow.

## 3. Critical issue (why this is a revise)

**`kenburns_24.py` and `pc_helpers.py` are not redacted by design on their failure paths.** The PowerShell scripts carry a `trap` precisely so that an unexpected error "never prints a red error (which can carry a folder name)", but the Python tool, whose output the wrapper shows live and unscrubbed, has no equivalent: an unexpected exception prints a full traceback (script path, output path, exit 1 instead of 3), and `scrub()` masks only the temporary work folder, so an ffmpeg error about the output file prints the output path in full. The README then tells the maker "If you see FAIL, paste the lines in chat". The orchestrator's `public_lint` would catch a pasted path before filing, but the hard rule is that the scripts redact by design, not that a later lint catches it. The fix is small (nudges 1 and 2).

## 4. Nudges (at most six; the first two are the revise)

1. **`win/kit2/kenburns_24.py`, `main()`**: after the `except pc_helpers.EnvError` clause add a catch-all `except Exception as e: print("kenburns_24: unexpected error (%s). Nothing of yours was changed; paste this one line in chat." % type(e).__name__, file=sys.stderr); return 3` (no `str(e)`, no traceback). Same in `pc_helpers.py main()`. Wrap `os.makedirs(out_dir, exist_ok=True)` in `run_job` so an `OSError` becomes `EnvError("cannot create the output folder for %s" % os.path.basename(out))`. Add a test in `kb_checks.py` (an `--out` under an existing file) asserting exit 3, no `Traceback`, and that neither the repo path nor the output path appears.
2. **`win/kit2/kenburns_24.py`, `scrub()` (line 329)**: scrub the output folder, the project folder and the home folder as well as the work folder: replace `out_dir` with `<out>`, `REPO` with `<project>`, `os.path.expanduser("~")` with `<home>` (longest first); pass `out_dir` down from `render_movie` and `make_zoompan_proof`. Apply the same to `pc_helpers.make_clip`'s tail (replace `os.path.dirname(out)`). Add the forced output-open failure from section 2 item 3 to `kb_checks.py` and assert the path is absent.
3. **`win/kit2/README-KIT2.md`, "Messages you may see" table (line 156)**: add the row for the new `unexpected error (...)` line and for `environment problem: ...` ("paste the one line in chat; it names no folder"). Line 203 states "the winget one is 9.0.2" as fact: write "(the winget build was 9.0.2 when the plan was read on 2026-10-18; UNVERIFIED)", as the install section already does.
4. **Drift guard for the copied helpers (maintainability)**: `Show-Path`, `Clean-Message`, `Quote-Arg`, `Invoke-Tool`, `Find-Exe` and `Find-Python` are pasted verbatim into three or four `win/kit2/*.ps1` files (and the pattern engine is a port of `win/step0_pc_tests.ps1`). Keeping the maker's scripts self-contained is fine; add one cheap test in `run_tests.sh` that extracts each shared function body (the regex in the quoting test already does this) from every kit2 script and asserts they are identical, so a fix to one cannot silently miss the others. A one-line header note "shared helpers: identical copies in kenburns_24.ps1, archive_*.ps1, run_checks_pc.ps1" also helps.
5. **`build/reports/WP-09.md` F-3**: the README example `field=ffmpeg.configure[12]` is fine as an example, but say in the README that the number is the position of the flag in the list (it already says "where in the record"); no code change. Also note for the orchestrator: `win/kit2/kenburns_24.py` is already tracked in the WIP checkpoint commit while the other kit2 files are untracked, so the commit of this package must include the modified tracked file too.
