## 2. Tests designed to break it

1. **Does the cleanup fix hold on both exit paths?** With `S` global and the trap text falling back to `/nonexistent-sp3-scratch`, a successful run (run 2, and my shim test) and a `die` inside the function both delete the right folder and neither can delete `/`. `lj_guard.sh` defines no `S`. **Held.**
2. **Is the host finding a measurement artefact?** Four lines moved by the same factor (1.96 to 2.06) with identical peak RSS, steal sampled at 1.1 percent, the first line clean (load 0.56) and already 2.06x; the later "contaminated" flags are the previous render's own load, as in run 1. A noisy-neighbour or self-load explanation would not give a uniform factor on a clean first line. The one thing the report could not do is name the cause, and it says so. **Held.**
3. **Is the table a fair yardstick at all?** The table's own header says it was measured on a "4 vCPU Intel Xeon 2.1 GHz" container, so the table is a run-1-class number, and run 1 reproduces it at 0.81x to 0.86x. On a run-2-class host the stand-in itself sits at 1.65x to 1.72x before any real frame exists, so a plain "within 2x the table" at G1 measures the host as much as the frame. The report's suggestion (time the stand-in's `64 1 0` line in the same session and record the CPU model) is the right repair and is correctly left to the orchestrator (nudge 6). **Held, with that caveat recorded.**
4. **Does the second fetch break the download discipline?** Run 2 fetched the same 402 MB wheel a second time with a reason (confirm the fix on a real install) but with no ledger row and no recorded exception, because pip fetches are outside the Craft ledger; `check_ledger.py` therefore reads 623.6 MB while the fortnight's true total is about 1.5 GB. Nothing identifying, nothing kept, within the 2 GB allowance, and the report states the arithmetic plainly, so this is a nudge (1), not a block.
5. **Can the next run destroy the evidence?** `run_inner` overwrites `build/evidence/wp10/sp3_results.txt`; the two-run file now in it was merged by hand, and the per-run copies live in `build/evidence/w2-sp3/`. A G1 run will overwrite the merged file again (nudge 3).
