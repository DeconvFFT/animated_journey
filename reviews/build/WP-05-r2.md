## Tests of my own, designed to break it

1. **Decode failure path leak (found).** A chain whose encode succeeds but whose output is not a video (`video_args: ["-c:v","rawvideo","-f","rawvideo"]` into a `.mp4`): the tool correctly reports it on the `could not be measured` line (exit 1), but the ERROR line and the raw record's `error` field read `... Error opening input file /tmp/lj_cp_l6fjitj7/p_raw_bytes_not_a_video.mp4.` The encode path scrubs `workdir` (`first_lines(se, work=workdir)`); the decode path calls `first_lines(err)` without it. On the maker's PC `tempfile.mkdtemp()` is under `C:\Users\<name>\AppData\Local\Temp\`, so the user name would be printed and written into the raw record. The derived form drops `error`, so nothing filed is affected; the header's promise that no path is recorded in either form is nonetheless broken on this path. Nudge 1.
2. **Odd output sizes through the new read-back.** `scale=854:480` (non-integer ratio to the grid) measures 0/255 `measured at 854x480`; `scale=3840:2160` measures 2/255 (accurate 1). Nearest-neighbour on flat patches holds both ways.
3. **Corrupted `mdat` under a fake-name folder** (`.../Users/<fake>/clip.mp4`): stdout, stderr and verdict JSON carry neither the name, the folder nor a heap address; `integrity.decode` FAILs with a sorted, de-duplicated detail; two runs identical.
4. **Planted mkv tags.** `-metadata:s:v:0 DURATION=hello` is overwritten by the muxer (so only timecode-shaped values ever reach the tool); a format-level `comment` holding a timecode is caught (`metadata.neutral` FAIL, value masked).
5. **`public_lint.py` on a file outside the root** now exits 2 with a USAGE line (WP-03's fix landed), so the harness guard and the lint agree.
