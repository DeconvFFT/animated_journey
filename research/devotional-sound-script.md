## Summary

1. **Indic text can lose its shaping silently in FFmpeg, and the project's own SRT template is the first case: `subtitles` is stuck in simple shaping up to n8.1.1; `drawtext` shapes Indic only from n9.0.** (a) In n5.1 to n8.1.1 the `shaping` option exists only on the `ass` filter, so for `subtitles` the context field stays 0, and `config_input` (shared by both filters) passes it to libass as `ASS_SHAPING_SIMPLE`; from n9.0 `shaping` sits in a `SHAPING_OPTIONS` macro expanded into both `ass_options` and `subtitles_options` at n9.0 and n9.0.2 (default -1, `auto`), so `subtitles` is `auto`, which is complex. Measured on nine scripts with one controlled string each: ffmpeg 6.1.1 `subtitles` is pixel-identical to `shaping=simple` and shows every broken tell (visible halant, stand-alone reph, unmoved short-i); a build of n9.0.2 `subtitles` is pixel-identical to `shaping=complex` and to 6.1.1's `ass`. The libass log line `Shaper: ... HarfBuzz-ng (COMPLEX)` is printed at start-up and is the same in both cases, so it is not a gate; the gate is a pixel test (`research/devotional-sound-script-fixtures/subtitles_vs_ass_shaping_2026-10-19.csv` and the picture beside it). The maker's PC has Gyan 9.0.2 per the sources, where `subtitles` is fine (UNVERIFIED until the PC test); anything run on ffmpeg 8.x or older (a different machine, a container, a build the maker did not choose) must use `ass` with an ASS made from the SRT (`ffmpeg -i in.srt out.ass`, then set the style in the ASS file) [96]. (b) In FFmpeg tags n6.1.1 to n8.1.1 `drawtext`'s HarfBuzz code sets `HB_SCRIPT_LATIN` before shaping (read in `libavfilter/vf_drawtext.c` at each tag); n9.0, n9.0.1 and n9.0.2 no longer do. I ran n6.1.1 (conjuncts fall apart: ksha comes out as the three glyphs Ka, Halant, Ssa; the reph is not formed, so dharma shows a stand-alone ra plus halant; the short-i sign stays after its consonant) and a build of n9.0.2 (all 72 test strings shape; the logged glyph count equals HarfBuzz's for every one, and the log prints `shape: script=Deva`). The maker's winget `ffmpeg` is Gyan's "release full", and its latest release is 9.0.2 dated 2026-09-19 [75][77]. The Windows binary itself is UNVERIFIED until the PC test. Kdenlive's bundled ffmpeg 8.1.1 has no `drawtext` at all (`research/toolchain.md`).
2. **The real danger is silent font substitution, not bad shaping.** The `ass` filter's libass shaped all nine scripts correctly with `shaping=auto` (identical frames to `shaping=complex`; `shaping=simple` shows every broken tell; see item 1 for why `subtitles` before n9.0 is the exception), but libass resolved the ten Anek families and the Catamaran variable file to Inter, FreeSans, FreeSerif or Unifont, because those variable files' default instance is not Regular (Anek default is Medium 500; Catamaran's is Thin 100) and name ID 1 does not equal the family you ask for. The picture looked "Indian" anyway. Fix: static instances, or the name libass sees ("Anek Telugu Medium"). A single-font SRT burn-in also falls back silently for any other script on the line; `<font face="...">` inside the cue fixes it. Proof is a log line, not a picture: `fontselect: (REQUESTED, 400, 0) -> FILE` [fixture `libass_fontselect_2026-10-19.txt`].
3. **Licences are clean.** All 109 families read are SIL OFL 1.1 in their own `OFL.txt` (copyright line, Reserved Font Name flag and SHA-256 recorded in `font_table_2026-10-19.csv`). Reserved Font Names: Arya, Charis SIL, Gentium Plus, Gentium Book Plus, Martel, Libre Baskerville, Lora, Merriweather, Playfair Display, PT Serif: do not rename-and-modify those; instancing a no-RFN variable font (Noto, Anek, Catamaran) is allowed. Video titling is a listed OFL use (FAQ 1.1); embedding is answered for documents and files, not video (FAQ 1.11 to 1.12) [74].
4. **"Latin included" does not mean "IAST included".** Of the Indic families, only Mukta (and Mukta Malar/Mahee/Vaani), Gotu and the Baloo 2 family carry the full IAST core set (all miss `ṁ` and the combining ring below); the Tiro family misses only `ḹ`/`Ḹ`, which no text here needs. Noto Sans/Serif Devanagari, Hind, Poppins, Yatra One, Rozha One, Khand, Martel and all Anek families lack most IAST letters, so a line mixing Devanagari and IAST falls to another face. Latin faces with the full set: Noto Sans/Serif/Display, Gentium Plus, Charis SIL, Cardo, EB Garamond, Cormorant Garamond (all measured) [fixture `iast_coverage_*.csv`]. Poppins, Hind and Yatra One also lack the Vedic svara marks (U+0951, U+0952).
5. **FontSize=23 is not a font-independent size.** libass pins the line pitch near 86 px (7.96 to 8.06% of 1080) for every font, so the *letter size* varies: the base letter KA is 2.22% of picture height in Noto Serif Devanagari, 2.59% in Noto Sans Devanagari, 3.06% in Mukta, 3.43% in Poppins, 3.98% in Noto Sans Telugu. Against the project's 3.1% caption floor several faces fail at 23. And one sample line (41 to 50 code points) fills the 90% box to 101% in Noto Sans Tamil (41 code points) and 100.9% in Noto Sans Malayalam (50), measured with complex shaping on n9.0.2 (a first run under simple shaping gave 105% and 111%, and 80% instead of 58% for Kannada): W-18's "42 characters" must become a width rule for those scripts [fixture `caption_size_*`, `caption_width_*`].
6. **"Devotional means free" is wrong five ways.** The text may be public domain (Tyagaraja d. 1847, Tulsidas d. 1623, Annamacharya d. 1503, Phillauri d. 1881) while the tune set to it, the arrangement, the recording and the performance are owned. Annamacharya's texts are free; the modern settings by named composers are copyrighted works. M. S. Subbulakshmi's Suprabhatam (HMV LP, November 1963) is out of Indian term on my computation (published 1963, term ends with 2023) but protected in the US until 2067-02-15 and in the UK to 2033 [1][13][16].
7. **India's `s.52` exempts nothing a public premiere is.** (za) covers performance or communication to the public in a bona fide religious ceremony (the Explanation adds marriage processions and social festivities of a marriage); (l) covers an amateur club's performance of a work to a non-paying audience or for a religious institution (a live performance of a work, not exhibition of a film); (j) and (k) cover educational institutions and residents' halls or non-profit clubs. A government notice read the religious-ceremony clause broadly; its reach is contested and untested in the Delhi High Court expert report [1][2][3].
8. **The Indian collecting-society map moved twice in 2026.** The Delhi High Court (2025-04) held PPL could not license member labels' recordings because it was not a registered copyright society; the government registered PPL on 2026-06-11 after RMPL's five-year term ended; Saregama had moved its recordings from PPL to Novex; IPRS (works) and ISRA (performers) are separate; a one-window portal, Sangeet Dwar, soft-launched 2026-02-06 for on-ground public performance [5][6][7][8]. IPRS's 2025 scheme prices a non-ticketed event at Rs 1,50,000 (other venues) and a small standalone banquet or auditorium event at Rs 12,000, but those tariffs describe live, DJ and background music; I found no IPRS tariff that names a film screening, so whether any applies is a T10 question [4].
9. **A licence field on archive.org is the uploader's claim.** "M.S. Subbulakshmi - Carnatic Concert (1999)" and "D.K. Pattammal - Classical Carnatic Songs (1995)" carry a Public Domain Mark; "VintageSense Vintage Indian Music" items (1968 film songs among them) carry CC BY 3.0 from a private uploader; the Great 78 Project says its audio is for "research, teaching, and private study only" [25][26]. The one item I could defend as public domain on its face is a 1906 Calcutta Gramophone recording (published before 1925 in India, the US and the UK).
10. **ND licences cannot go under picture; NC and SA need thought.** CC 4.0 says a recording "synched in timed relation with a moving image" is always Adapted Material; CC 3.0 calls it an Adaptation. So BY-ND and BY-NC-ND audio (RaagaDhvani flute, the CompMusic site badge) is out. Saraga 1.5 is BY-NC-SA 4.0; Sanidha (Carnatic multitrack) is CC BY 4.0 but access means emailing a university, which conflicts with secrecy [28][29][30][31][32][33].
11. **AI music tools are a poor fit and the lean stands.** Suno terms (revised 2026-08-10, effective 2026-09-03; re-read today): free-plan output may be used only for "lawful, personal and non-commercial purposes", paid plans get an assignment of whatever Suno owns, no warranty of copyright, a voice model only of your own voice. Udio: downloads off since the 2025-10-29 settlement and output limited to personal use. ElevenLabs Music (updated 2026-10-09): film, TV and radio excluded below the Enterprise tier. Stable Audio 3.0 runs locally under the Community Licence (free commercial use under USD 1M revenue). MusicGen weights are CC-BY-NC. ACE-Step is Apache 2.0 but does not name Hindi or Sanskrit among its languages. No source I found tests any of them against raga grammar, gamaka or tala [58][59][60][61][63][64][68]. The ISKCON News piece records devotees who felt AI output lacked "living consciousness"; a Rajya Sabha reply (2025-12) confirms AI-created devotional songs were aired on Prasar Bharati's network on a pilot basis; I found no organised backlash, but my search budget was short [66][67].
12. **Tradition does not fix raga-to-rasa; the film's mapping is ours.** Hindustani time-of-day windows differ between sources (Todi 8 to 10 am or 9 to 12; Bilaval 4 to 8 or 6 to 9); Carnatic practice places "less emphasis on time or season"; the sources give mood words for some ragas (Bhairav "solemn peacefulness", Kharaharapriya karuna, Reetigowla "bhakti mixed with immense joy") and none for others. The raga table in Template B quotes the tradition and then offers a rasa as inference. Her own tune's raga is unknown and must stay unknown unless a teacher names it.
13. **Origin flags, not rulings.** Shared or non-Hindu history: sitar (first named in 1739 and absent from pictures before 1790 per Miner's reviewer; the Persian setar descent is stated by secondary pages), sarod (Afghan rabab, about 1830), tabla (contested; clear pictures only from about 1745), shehnai (Persian name; also temple use), santoor (Iranian, "directly borrowed"), khayal (a Persian/Arabic word; shaped in the Delhi Sultanate and Mughal courts), the harmonium (French reed organ that arrived "possibly with missionaries or traders" in the mid-19th century; banned from All India Radio 1940 to 1971; now ubiquitous in bhajan), ektara (Baul and Sufi use beside kirtan), and the tanpura (Sanskrit lineage, but the modern form is first drawn in Mughal-era paintings). The maker rules; one-line questions are in Template C and the open questions.
14. **The Fable watch-out about phones is half right.** On a crude phone model (a 300 Hz or 500 Hz high-pass) the CC0 conch, bell, koel, pressure cooker and the PD mridangam strokes lose under 4.2 dB, and a real tanpura sample keeps 96% of its energy above 300 Hz (the buzzing jawari partials), while room rumble and low "temple ambience" lose about 20 dB. So: drones do not vanish, their body does; room tone and low rumble do. Phone-speaker bass cut-off is a rule of thumb of about 250 to 500 Hz [87]; the maker's own sweep decides.
15. **Sound capture must respect D-05 as well as D-17.** The premiere cut carries no recorded voice of any living person except her own HER-PUBLIC clip, so aarti, kirtan, temple loudspeaker and the 6 a.m. devotional radio are out as *content*; the conch, bell, lamp, cooker, grinder and the empty-room tone are in, recorded by the maker when the house is empty. Generic CC0 stand-ins exist (an Indian temple bell, a Kolkata dhaak, a koel) but Principle 2 says a generic Indian sound is out unless it is hers.
16. **D-31 changes the keys, not the rules.** Gujarati language, a Pushtimarg Vaishnav family, an Android phone. Gujarati fixture 5 to 18 strings, 6 to 11 families: **Hind Vadodara has no Gujarati digits** (silent fallback; I had put it first), Farsan has no Om sign, Kumar One collapses under libass (its hinting program fails in FreeType; Follow-up 6), Mukta Vaani draws half-form conjuncts, and Noto Sans Gujarati is the safe caption face. Her tradition's texts are 15th- and 16th-century and clean (Narsinh Mehta, Vallabha, the Ashtachhap); its tunes, arrangements and recordings are not; the harmonium is named inside her sampradaya's temple music by a tagged Wikipedia page, a 2026 peer-reviewed paper and a 2021 field study, while the bansuri's exclusion is claimed by the tagged page alone and is contested by the paper's instrument list (Follow-up 1); this sharpens the O-41 question and still warns against a stock "Krishna flute" bed (Principle 2). D-05 and D-07 still keep the tradition's audio out of the premiere. Template N, section "D-31 update".

**What this means for the sound plan.**
1. **The premiere rules hold.** D-05 and D-07 mean her tradition enters the premiere as card text, silence, the maker's own capture of non-voice sounds (Template I), and instrumental cleared cues (Template F). The tradition-specific audio (a haveli kirtan, a garba, an aarti) is an April or later matter.
2. **The text side is rich and clean.** Narsinh Mehta, Vallabha and the Ashtachhap are 15th- and 16th-century authors, out of every term; the two-line verse card (her script, then the maker's plain line) can be built from them, once she has said which lines are hers. The shaping fixture now covers the marks those lines need (visarga, anusvara, candrabindu, Om sign, vocalic r, digits).
3. **Do not buy a generic "Krishna flute" bed.** Principle 2 already says a generic Indian sound is out unless it is hers; one maintenance-tagged page adds that her sampradaya's temple custom keeps the bansuri out of the sanctum [88], a claim that a 2026 paper's list of instruments of divine service (which includes Murali) does not support [97] (contested; UNVERIFIED), while the temple's own blog shows the deity's flute placed in his hand, withheld or offered darshan by darshan [99]; either way a stock bansuri cue is the generic cliche Principle 2 rejects and could clash with her tradition. Ask the maker (question 12).

### Q1. A raga-and-time-of-day map, Hindustani and Carnatic, keyed on the rasa sheet

**What the sources give.** The full table is Template B (24 rows, each with its source). The framework: the Hindustani day is eight prahars of about three hours; Sarngadeva (13th century) tied ragas to times of day and Nanyadeva (11th) to seasons; the North Indian system keeps the association and "the South Indian system is closer to the text, and places less emphasis on time or season" [39][40]. A blog summary gives a rule of thumb that shuddha Ma ragas sit in the first half of the day and tivra Ma in the second, with exceptions [43]. The site `gandharvshastra` states sandhiprakash (twilight) ragas use komal Re and shuddha Ga at 4 to 7 am and 4 to 7 pm [40]. **The windows disagree across pages** (Todi: "approximately 8-10AM" in the text and "9-12" in the infobox; Alhaiya Bilaval: 4 to 8 am in the infobox and the first prahar 6 to 9 in the body; Yaman: "first quarter of the night" and, per *The Raga Guide*, 9 pm to midnight; Hamsadhvani: "early night 9-12" with no page-stated mood) [39]. Treat every window as a tradition's label, not a rule a viewer will test.

**Rasa is not fixed by tradition.** Wikipedia: "Each raga traditionally has an emotional significance and symbolic associations such as with season, time and mood", but the page gives no fixed raga-to-mood mapping [39]. Where a page gives a mood I quote it; where it gives none the table says "none stated" rather than inventing one. The film's rasa column (from `research/hindu-frameworks.md` Template B: śānta, karuṇa, śṛṅgāra (decorous), vīra (quiet), hāsya, adbhuta, vātsalya) is **our inference**, flagged as such. Vātsalya has no raga in any source I read; the lullaby cue is the hummed tune (W-44), whose raga is unknown.

**The brief's leads checked.**
- *Dawn and morning:* Bhairav ("Daybreak", opens concerts; Pandit Jasraj: "solemn peacefulness is its ideal mood"; rasa "Shaant aur Gambhir") [39]. Todi (morning; "pensive, mournful", relieved by a festive fast section) [39]. Bilaval (Alhaiya; "Shant Rasa") [39]. **Bhupali's "morning use": not supported by any page I read.** Bhoopali is listed "early night, 7-9 PM" with "Bhakti rasa" and "Shanti Rasa", and Gandharv Shastra files it under the night prahar [39][40]. UNVERIFIED lead; the Carnatic equivalent Mohanam has no time rule.
- *Afternoon:* Bhimpalasi (early afternoon 12 to 3; no mood on the page; Carnatic Abheri) and Brindavani Sarang (noon to afternoon; "sringara rasa" and Veer rasa; created by Swami Haridas, who "brought Lord Krishna to earth" through it; Carnatic Brindavani) [39].
- *Evening and night:* Yaman (soothing and auspicious; Carnatic Kalyani), Puriya Dhanashree (dusk, sandhiprakash; no mood stated), Malkauns (late night 12 to 3; "serious, meditative"; Ali Akbar Khan: devotion, peace, heroism; Hindu legend that Parvati created it to calm Shiva; also a Jain use), Durga (second prahar of night; "sringara rasa"; named for the Goddess), Bageshri (9 pm to midnight; "waiting for reunion with one's lover"; the page lists the rasa as Hasya, which sits oddly with that sentence; "traces its origins to the Samaveda") [39].
- *The concluding Bhairavi:* "Morning; Conclusion of a concert", "queen of morning Ragas", "the closing Raga for any formal performance", "a rich, devotional atmosphere", suited to bhajan and thumri [39]. The Carnatic closing ragas: Madhyamavati ("every Carnatic music concert ends with" a piece in it; "very auspicious"; no mood stated; Hindustani counterparts Madhumad Sarang, Megh, Megh Malhar), Kalyani (opens concerts "because it is considered auspicious"; prominent in South Indian weddings), Hamsadhvani (pentatonic; created by Ramaswami Dikshitar 1735 to 1817; "usually sung at the beginning of a performance"), Shankarabharanam ("mellifluous and smooth"; Dikshitar's Shiva kritis), Kharaharapriya (karuna rasa; Tyagaraja's raga; legend of Ravana singing to Shiva), Sindhu Bhairavi (Viraham, Shokam, Karunam, Bhakthi), Reetigowla ("Bhakti mixed with immense joy") [39]. A closing-mangalam essay names Madhyamavati, Surati and Saurashtram as the preferred mangalam ragas (SR) [SR: Dhvani Ohio essay, source 43].
- *Seasonal:* Malhar is "strongly associated with the monsoon", with rasa tied to rainy-season longing; variants Miyan ki Malhar, Megh, Gaud, Sur and Ramdasi are "distinct ragas"; the legends credit Tansen and also Meera Bai with calling rain [39]. Desh: second quarter of the night, 9 pm to midnight, no season or mood on the page; used in "Vande Mataram" and in Tagore's songs [39]. **Desh as a seasonal raga is UNVERIFIED** (one search snippet listed it with monsoon ragas, truncated).

**Public-domain or freely licensed examples.** For most of the ragas above I found none that is genuinely public domain and clean. The items that came closest are in Q5. The reason is structural: published raga performances are label property, and the freely licensed ones are research corpora (NC, SA or ND) or individual uploads with unverified provenance.

**Can an agent-made bed carry a raga honestly?** The evidence: no peer-reviewed test of Suno or Udio against raga grammar, gamaka or tala turned up in my searches; a 2023 AIMC paper on a different system lists microtonal adjustment as a planned feature; a critical essay found Suno and Udio raga prompts "finished but empty"; vendor claims (RaagEngine, Sargam AI, a MusicSeed guide) are marketing and untested [68]. MusicGen's own card says it "does not perform equally well for all music styles and cultures" and cannot make realistic vocals [63]. Todi's identity rests on komal Re, Ga and Dha "intoned low" and a very sharp tivra Ma [39], which is exactly what a generic bed flattens. **Verdict by cue:** a bed may carry a **drone** (Sa-Pa or Sa-ma), a **bell/conch/lamp** texture and **room tone**; it may not carry a **named raga's melodic phrases**. If a pentatonic pad sits in a raga's scale, call it a "mode", never the raga name (the brief's "a claimed raga that breaks its grammar is a tell"). The drone has an honesty problem of its own: the one open-access tanpura set I found has no licence and the author does not know who recorded it [36].

### Q2. Instruments and timbres with origin flags

Full table: Template C. What changed from the brief's grouping:
- **Moved from "unambiguous" to flagged: ektara.** The Wikipedia page lists it as common in Baul music, in kirtan chanting, and "used by Hindu Sadhus and Islamic Sufi saints" (one-string form); Bauls are a Bengal syncretic tradition [50]. Flag SHARED (Baul and Sufi use beside Hindu kirtan).
- **Tanpura:** "Tumburu Vina" in Sanskrit, drone described in the Natyashastra without a name, and the modern form first depicted around the 16th to 17th centuries; "Early Mughal paintings during this time illustrated scenes of a tambur player" [52]. Flag SHARED-LIGHT (Hindu lineage, Mughal-era first pictures). The page does not discuss deity iconography, so "Narada's instrument" is UNVERIFIED here.
- **Sitar:** the first use of the word dates to 1739, tied to a Khusrau Khan; "aucun sitār n'y apparaît avant 1790" in iconography; the Amir Khusrau attribution is a later confusion (Miner's reviewer; the Persian setar descent is stated in the Wikipedia and secondary pages, not in that review) [46]. Flag COURT.
- **Sarod:** descends from the model played in Afghanistan, Pakistan and Kashmir; first mention about 1830; metal fingerboard about 1860 by Na'matullah Khan of Calcutta [46]. Flag COURT/AFGHAN.
- **Tabla:** contested. Bhaja cave carvings (c. 2nd century BCE) and 6th to 7th century temple carvings are cited for an indigenous origin, though "it is not apparent in any of these ancient carvings that those drums were made of the same material and skin"; the name may come from Arabic *tabl*; the Amir Khusrau and pakhawaj-splitting stories lack any contemporary support ("cannot be given any credence", Sorrell and Narayan); the Ain-i-Akbari list omits it; "Clear pictorial evidence of the drum emerges only from about 1745" [47]. Flag SHARED (disputed).
- **Shehnai:** two accounts (descent from the folk pungi; descent from a Persian surna), a name from Persian *shah* and *nai*, a place in the royal naubat and in temples and weddings; Bismillah Khan's uncle played at Kashi Vishwanath [54 SR]. Flag SHARED.
- **Santoor:** "a hammered dulcimer of Iranian origin"; the Indian santoor "directly borrowed from the Persian santoor" [48]. Flag SUFI/PERSIAN. (The Sufiana Kalam link is not on the page I read.)
- **Harmonium:** reed organs reached India "during the mid-19th century, possibly with missionaries or traders"; Indian craftsmen made the smaller hand-pumped, floor-played form; "banned from All India Radio from 1940 to 1971" because it cannot do slurs, gamaka or meend and as "an unwanted foreign interloper"; "still widely used today by Sikhs, Hindus, Muslims and Buddhists" for bhajan and kirtan; in South India it is used mostly in devotional music and harikatha [44]. Britannica (SR) agrees on the 1940 to 1971 ban. The page is flagged as needing more citations. Flag COLONIAL_EUROPEAN (the missionary channel is "possible", not proven, so not CHURCH) and the one-line question on O-41.
- **Khayal (form):** a Persian/Arabic word for "imagination" that "entered India through the medium of the Persian language"; "Most scholars agree that khyal was the outcome of a gradual process of evolution that occurred in the Delhi Sultanate"; the Sharqi rulers patronised it; Sadarang (Niyamat Khan) shaped it at Muhammad Shah's court; bandish topics include "the pranks of Krishna" [49]. Flag COURT.
- **Pakhawaj:** a Prakrit-origin name (Sanskrit *pakṣavādya*), wooden body from the 14th century, "the percussion instrument most commonly used in the dhrupad style"; Nathdwara is a surviving gharana [51]. The page says nothing on the Mughal court. Flag NONE with the dhrupad-at-court question UNVERIFIED.
- **Nadaswaram and thavil:** a *mangala vadyam* ("very auspicious"), in "almost all Hindu weddings and temple ceremonies of the South Indian tradition", mostly outdoors because of its volume [53]. Flag NONE.
- **Not researched with a page opened:** shankha, ghanta, damaru, manjira and kartal, mridangam (beyond the tabla page's legend), chenda and edakka, dhak (only the Kolkata Durga Puja recording description), veena, bansuri. ### Q4. The rights matrix per source type

Table: Template E, with the T10 additions. The structure of the answer:
1. **India, what is a "work" and what is a "recording".** The Act keeps the song (musical work), the sound recording and the film as separate things: "The copyright in a cinematograph film or a sound recording shall not affect the separate copyright in any work in respect of which or a substantial part of which, the film, or ... the sound recording is made" (s.13(4)); a "cinematograph film" "includes a sound recording accompanying such visual recording" (s.2(f)) [1]. Terms: works, life plus 60 from the next year (s.22); sound recordings, 60 years from the next year after publication (s.27); performers, 50 years from the next year after the performance (s.38(2)) [1]. Moral rights of performers (s.38B) exist "independently of his right after assignment": the right to be identified and to restrain distortion or mutilation prejudicial to reputation; mere editing for length or technical reasons is not prejudicial [1].
2. **Assignments must be written and specific.** s.19: signed writing; identify the work; specify rights, duration and territory; state royalty or other consideration; "If the period of assignment is not stated, it shall be deemed to be five years"; "If the territorial extent ... is not specified, it shall be presumed to extend within India"; an unused right lapses after one year unless the assignment says otherwise; s.19(9) and (10) leave authors an equal share of royalties for uses other than "communication to the public of the work, along with the cinematograph film in a cinema hall" and for sound recordings not part of a film [1]. A performer who "by written agreement, consented to the incorporation of his performance in a cinematograph film" cannot object to the producer's use, but "shall be entitled for royalties in case of making of the performances for commercial use" (s.38A(2)) [1]. Under s.17 the author of a work stays first owner of it even when it is incorporated into a film (the proviso) [1].
3. **What `s.52` exempts (the leads).** (j) performance in the course of an educational institution's activities to a limited audience; (k) a recording "caused to be heard in public" in a residents' hall or as part of a non-profit club's activities; (l) "the performance of a literary, dramatic or musical work by an amateur club or society, if the performance is given to a non-paying audience, or for the benefit of a religious institution"; (za) "the performance of a literary, dramatic or musical work or the communication to the public of such work or of a sound recording in the course of any bona fide religious ceremony or an official ceremony held by the Central Government or the State Government or any local authority", with the Explanation "religious ceremony including a marriage procession and other social festivities associated with a marriage" [1]. **A film premiere is none of these**: (za) needs a religious ceremony (a puja or aarti *performed live at the gathering* might be inside it; the film's soundtrack is not); (l) is a live amateur performance of a *work* (not a recording or a film) and an invited audience at a free event helps only that; (j) and (k) need an institution, residents or a non-profit club. A government notice (reported 2019, SR) read (za) as covering recorded music at weddings and religious ceremonies; commentators dispute that reading, a Delhi High Court-appointed expert (Scaria) examined the clause's "social, cultural, historical and legal dimensions" in 2022 and the scope "remained largely untested" [2][3]. A 2009 Gujarat High Court decision is summarised (SR) as stressing absence of commercial purpose [3]. **UNVERIFIED, not legal advice; goes to the T10 consult, and applies only if the premiere is in India (O-02).**
4. **Who collects, India, 2026-10-19.** IPRS (works; the 2025 scheme, written for 55th AGM approval, in force from 1 April 2025 per its own text); PPL (recordings; registered as a copyright society 2026-06-11 after the Delhi High Court's April 2025 holding; roughly 450 to 500 labels including the three majors, T-Series, Times Music, Lahari, Aditya); Novex (Saregama, Tips, YRF Music and Zee Music Company; not a registered society in the 2025 reporting); RMPL (registered 2021, five-year term ended); ISRA and ISAMRA (performers); Sangeet Dwar (a one-window portal for on-ground public performance, soft-launched 2026-02-06) [4][5][6][7][8][9][10]. The Supreme Court on 2025-04-21 stayed only the direction to pay at RMPL's tariff, not the holding [9 SR]. **I found no source that says what any of them charges for a private-hire film screening;** the IPRS tariffs I could read name live, DJ and background music (Template E).
5. **Abroad.** *US:* sound recordings have no general public-performance right: §106(6) gives only "to perform the copyrighted work publicly by means of a digital audio transmission" and §114(a) says their rights "do not include any right of performance under section 106(4)"; §110(4) exempts a non-profit performance of a "nondramatic literary or musical work" with no admission charge and no payment to performers, promoters or organisers, but says nothing about sync or master [15]. Movie theatres get "a single license from a movie's distributor that covers all of the various rights embedded within a single feature" (DOJ consent-decree comments, SR) [24]. Pre-1972 recordings: foreign-published before 1925 are public domain, 1925 to 1946 run 100 years from publication, 1947 to 1956 110 years, 1957 to 14 Feb 1972 to 15 Feb 2067 [16]. *UK:* PPL PRS's TheMusicLicence page says it "legally covers ... live music performances, open mic nights, karaoke, comedy shows and film screenings" (cost examples "correct as of September 2026"); "the sound track accompanying a film shall be treated as part of the film" (CDPA s.5B(2)) [18][19]. *Canada:* "sound recording ... excludes any soundtrack of a cinematographic work where it accompanies the cinematographic work" (Copyright Act s.2), so Re:Sound's recording tariffs are unlikely to bite on a film soundtrack; SOCAN (works) and Re:Sound issue licences together through Entandem; Re:Sound's event Tariff 5 lists years ending 2015 [20][21][22 SR]. *Australia:* OneMusic's Film Screenings licence is needed "regardless of whether there's an entry fee" with a minimum of AUD 86.52 shown for APRA works in July 2026 (sibling note's read; OneMusic returned 403 today) [R1, its source 51]. Whether a venue's blanket PRO licence covers a *film's* music, and whether a sync licence includes performance rights, are T10 questions.

Gujarati has no shirorekha (the headline bar) and its own digits, and sits in Unicode U+0A80 to U+0AFF with the candrabindu at U+0A81 and the Om sign at U+0AD0 [95].
- **"A display face with a beautiful sample can lack the conjunct a card needs."** The conjunct matrix (all 1,369 consonant pairs per Devanagari font) measures *ligature richness*: Tiro Devanagari Sanskrit fuses 328 pairs into one glyph; Mukta 294; Rozha One and Khand 300; Poppins, Hind and Yatra One about 290 to 295; Noto Sans and Serif 74 and 79 (they use half forms instead); Martel 89; Amita 85 [fixture `devanagari_conjunct_pairs_*.csv`]. Fewer fused glyphs is not wrong, it is a different typesetting style (half-form stacks); but a shloka card meant to look like a Sanskrit print will look different in Noto than in Tiro Sanskrit. The rule is the maker's: every card string is rendered through the real pipeline and inspected at 200% before G1.
- **Latin that carries IAST:** Noto Sans, Noto Serif, Noto Sans Display, Noto Serif Display, Gentium Plus, Gentium Book Plus, Charis SIL, Cardo (all full core; Cardo lacks `ṟ ṉ ḻ`), EB Garamond, Cormorant Garamond (Light is the variable default), Source Serif 4 (misses `ṁ`). - **IAST vs ISO 15919 vs popular spelling.** IAST was formalised on 10 September 1894 by the Geneva Oriental Congress; "Only certain fonts support all the Latin Unicode characters essential for the transliteration of Indic scripts" [84]. ISO 15919 (2001) writes vocalic r as `r̥` (ring below), anusvara as `ṁ` rather than `ṃ`, and marks long `ē`, `ō`; "The use of ē is considered optional" [83]. For a mostly non-Indian room: **popular spelling on screen** (Krishna, Lakshmi, Ganesha); **IAST only where a verse card exists and the maker wants it**, preferably in the printed programme; ISO 15919 not at all. Netflix's Hindi guide says to transliterate character names when no approved translation exists and has "no specific rules for Sanskrit words" [81].

### Q10. Shaping: ffmpeg/libass, drawtext, browsers

- **libass.** HarfBuzz is "Require[d] ... unconditionally to ensure good shaping for complex scripts" from libass 0.15.0 [76]; the container's libass is 0.17.1 (the newest changelog heading is 0.17.5). Gyan's essentials list shows "libass libfreetype libfribidi libharfbuzz" [75]. In FFmpeg's `libavfilter/vf_subtitles.c` the `shaping` option (`auto` default, `simple`, `complex`) sits in `ass_options` only at tags n5.1, n6.0, n6.1.1, n7.0, n7.1.1, n8.0, n8.0.1, n8.1 and n8.1.1 (each read), and in a `SHAPING_OPTIONS` macro expanded into both `ass_options` and `subtitles_options` at n9.0 and n9.0.2 (default -1, `auto`); `config_input`, used by both filters, calls `ass_set_shaper` whenever the field is not -1 [96]. So before n9.0 the `subtitles` filter (the project's SRT template) always runs libass in simple mode: `ffmpeg -h filter=subtitles` on 6.1.1 lists no `shaping` and `subtitles=...:shaping=complex` fails with "Option not found", while the same help on the n9.0.2 build lists it. The doc text in master says complex is "Required for correct rendering of complex scripts such as Arabic, Hebrew, Devanagari and Thai. Requires libass to be built with HarfBuzz" [77]. I rendered contact sheets of the fixture in all nine scripts in `complex` and `simple` and looked at every `complex` frame; for Devanagari `auto` and `complex` gave byte-identical frames, and `simple` gave every named tell (visible halant in क्ष and ज्ञ, standalone reph in धर्म, unmoved short-i in कि क्षि). In `complex`, as seen on the frames: Devanagari ksha, tra, jna, shri, dharma, mātṛdevo bhava, kṛṣṇa, the short-i reorder, Om and danda, Vedic marks, nukta and ZWJ/ZWNJ; Tamil shri and split vowels; the six Malayalam chillus (atomic code points shape in every tested face; the legacy ZWJ sequences render as a visible virama in Baloo Chettan 2); Bengali conjuncts, reph and ra-zophola; Telugu and Kannada vowel signs; Gujarati, Odia and Gurmukhi conjuncts and marks. SRT input must be UTF-8: a UTF-16 SRT is an error ("Invalid UTF-8 in decoded subtitles text"), a UTF-8 BOM is fine.
- **drawtext.** Docs from release/6.1 through master say `text_shaping` attempts to shape text "(for example, reverse the order of right-to-left text and join Arabic characters)" and that the filter needs `--enable-libfreetype` and `--enable-libharfbuzz` [77]. - **Browsers.** HarfBuzz "is used in Android, Chrome, ChromeOS, Firefox, Flutter, ... Microsoft Edge" [80]; Apple platforms are not on that list (iOS Safari's engine is UNVERIFIED here). Chromium was not run. The Devanagari analogue is not defined anywhere I read; designers align the shirorekha (headline) with the Latin x-height rather than the matra height, and say Devanagari "has no true x-height" [85 SR]. I use **KA height of at least 3.1% as the working analogue** (inference). (c) Size so the KA floor is met: `FontSize = 23 x 3.1 / (KA at 23)`: Noto Sans Devanagari about 27.5 (pitch about 9.5%), Noto Serif Devanagari 32, Mukta 23.3, Tiro Sanskrit 23.3, Hind 22, Poppins 21, Baloo 2 22.6, Gotu 21.4; Gujarati: Noto Sans Gujarati 21.4 (so 23 is enough), Baloo Bhai 2 22.6, Rasa 23.3, Mukta Vaani 24.1, Noto Serif and Anek Gujarati 25.6. A larger FontSize raises the pitch and the two-line block (12 to 15.5% of picture height at 23). (d) Width (complex shaping, ffmpeg n9.0.2 `subtitles`, FontSize 23, one sample sentence of 40 to 51 code points per script; fixture `caption_width_*`): 47.5% of the 90% box in Noto Sans Devanagari, 50.6% in Mukta, 56.4% in Tiro Sanskrit, 60.5% in Noto Sans Gujarati (44 code points), 63.0% Bengali, 55.3% Telugu, 58.2% Kannada, 71.6% Odia, 70.0% Gurmukhi, 88.9% in Hind Madurai, **101.0% in Noto Sans Tamil (41 code points), 100.9% in Noto Sans Malayalam (50)**. The first run of this table used the 6.1.1 `subtitles` filter, which shapes in simple mode, and overstated Tamil (104.9%), Malayalam (111.0%), Kannada (79.7%), Odia (81.2%), Bengali (69.2%) and Telugu (61.2%); Devanagari and Gujarati barely moved because the sample has few conjuncts. Maximum code points in the box: Tamil 40 (Noto) or 46 (Hind Madurai), Malayalam 49, Gujarati 72 (Noto Sans) to 90 (Anek). So for Tamil and Malayalam W-18 becomes: **a caption line must fit the 90% box at the chosen face and size; the count of 42 is a guide, not the rule; break at word boundaries only** (a word may be long; W3C's Indic draft allows a hyphenated break only at orthographic-syllable boundaries [79]).
**L2. Phone.** Assume a 6.1-inch 19.5:9 phone (about 64.9 x 140.7 mm; computed). Landscape, 16:9 picture fitted to the height: picture height about 64.9 mm. Portrait letterbox, picture fitted to the width: about 36.5 mm. KA at 3.06% (Mukta, FontSize 23) is about 2.0 mm in landscape and 1.1 mm in portrait; at 35 cm viewing that is about 19 and 11 arc minutes. A 20:9 phone showing the 16:9 picture full-bleed crops about 10% of the picture height at the top and bottom (computed: 16:9 scaled to fill a 20:9 width is 11.25 units against a 9-unit screen), so a caption sitting in the 5% margin is half cut. **The mobile-delivery track owns the phone caption pass; these numbers are inputs:** portrait needs a separate phone render (captions larger and in the letterbox bar or lifted above 12% from the bottom) or the viewer must rotate the phone. The arc-minute thresholds for comfortable reading were not sourced here (UNVERIFIED); the maker's 50-plus reader on her own phone decides.
**L3. Bilingual layout under W-18 (two lines, never three).**
1. The **caption track carries the room's language only**, two lines of at most the box width, 20 cps or slower (Netflix: 22 cps adult, 18 children for Hindi and Tamil [81][82]).
2. **Her script appears as title art** under the title system (T2 decision 4 in `cinematic-quality.md`): the film title in the room's language with her script as the second line of the *title card*, not a caption. Shape the string once with HarfBuzz and convert it to outlines (SVG or PNG); the card then cannot fall back to another face on any player.
3. A **verse or blessing card** (hindu-frameworks cap of two cards by default, never more than five) is two lines: line 1 her script (or Sanskrit in Devanagari), line 2 the maker's plain line in the room's language. **IAST is not a third line**; it goes in the printed programme or the archive text.
4. A sung or spoken line in her language: no recorded voice before April (D-05); in the April version the caption is the room's language and her language is heard.
5. A mixed Latin and Indic caption line: choose one family that holds both (Mukta, Tiro, Baloo 2, Gotu), or wrap the other-script run in `<font face="...">` in the SRT (verified) or `{\fn...}` in ASS; never one `FontName` for the whole file.
6. Names in the room's language: popular spelling (Krishna, Lakshmi, Ganesha); a deity named in a caption only if hers (O-38).
7. Phone render: lift the caption block, enlarge, check at 200%; do not restyle the venue file (W-18).
8. Sidecar SRT/VTT: UTF-8; `lang` tag on each cue where the player supports it.
**L4. Romanisation.** IAST (Geneva, 1894): `ā ī ū ṛ ṝ ḷ ḹ ṃ ḥ ṅ ñ ṭ ḍ ṇ ś ṣ`, a convention not a standard; ISO 15919 (2001): `r̥`, `ṁ`, `ē`, `ō`, for scholarly Indic including Dravidian; popular spelling: no marks. Use popular spelling on screen; IAST for a verse card only if asked; ISO 15919 never. Font support for IAST is uneven even in book faces [84], and the fixture shows eight of the Indic families that include "Latin" lack nearly all of it.

## Exclusions and ambiguous cases (under the maker's Hindu-only rule, D-28)

- **Out by the rule:** ghazal and qawwali (Sufi, Persianate); the santoor in a Sufiana context; any Mughal-court form as a *motif* (khayal as a named form; the sitar and sarod as showpieces).
- **Flagged for the maker (default `ASK`, silence in the render until ruled):** harmonium, tabla, shehnai, sitar, sarod, santoor, khayal, tanpura (light), ektara, the Carnatic violin (UNVERIFIED), the nadaswaram and chenda only if the maker wants the strictest reading (the chenda is also played at church festivals in Kerala; UNVERIFIED).
- **Yaman and Malhar, Todi:** their names carry Persian-court or Akbar-court attributions on the pages read; the ragas are used in Hindu devotion. A raga name never appears on screen; if a name is needed, use the Carnatic Kalyani or no name.
- **Desh:** political and Tagore associations; avoid as a motif.
- **Gurbani and Sikh kirtan, Jain and Buddhist chants** (including the Mahabodhi garden recording on Freesound): dharmic, not Hindu; out unless the maker rules.
- **Shyama Sangeet by Tagore or Nazrul:** restrict to the Shakta line (`hindu-frameworks` flag 14).
- **Faith of performers and composers.** D-28 is a rule about motifs and the world of the film. Famous film bhajans are often made by Muslim composers, lyricists or singers (my general knowledge, UNVERIFIED here); whether that matters is the maker's call and the question is asked once (Open question 5). Default in this note: a performer's faith is not a motif.
- **A famous singer's historic recording** (for example the 1963 Suprabhatam): the premiere cut bars the recorded voice of a living person (D-05) and "the dead animated or voiced" (W-46); whether W-46 reaches a historic recording used as music is Open question 4.
- **"Raghupati Raghava Raja Ram":** a version with an "Ishwar Allah" line (UNVERIFIED) needs a decision.
- **Dharmic cousins in the sample libraries:** CC0 "kirtan" uploads with many voices (D-05).
- **Sound that is the temple's, not hers:** an aarti recorded in a temple she does not attend is generic and out.

## Open questions for the maker

1. **O-36 (language answered by D-31; script still open).** D-31 says Gujarati. Does she read Sanskrit verse (the Krishna mantra, Yamunashtakam) in Gujarati or in Devanagari script, does she pray in Gujarati, Braj Bhasha, Hindi or Sanskrit, and which script should the title art use? The Gujarati set (18 strings) and the Devanagari verse strings both go on the settings card on Sun 1 Nov; this decides the title art and the verse cards.
2. **O-41, the harmonium and tabla.** *If her own bhajans are sung with a harmonium or tabla, do you keep them because they are hers, or does your Hindu-only rule take them out of the sound of the film?* (The harmonium arrived in the colonial period by a route the sources call "possibly" missionary; tabla's origin is disputed; the harmonium is named among the instruments of her sampradaya's temple music by a maintenance-tagged page [88], a 2026 peer-reviewed paper [97] and a 2021 field study [98]; I do not decide.)
3. **Sitar, sarod, santoor, khayal.** Do you want these out by default (my recommendation: out unless a family source says they were hers)? The shehnai, tanpura, ektara and the Carnatic violin are `ASK` (Template C): silence in the render until you rule.
4. **D-05 and W-46.** Does "no recorded voice of any living person" cover a temple's chanting crowd at a distance, a radio, and does "the dead ... voiced" cover a famous singer's historic recording used as music (for example the 1963 Suprabhatam)? And how do W-44's "a relative's public-domain performance" and D-05 fit together for a sung recording?
5. **Performers' and composers' faith.** Is D-28 about the motifs and world only (my default), or should the faith of a performer or composer also count?
6. **The tune she sang (O-41).** Is it traditional or a film or album song? Can you place it without uploading your hum to a song-identification service (D-15)? Until then the MOTIF row stays `composition_status=unknown`.
7. **The premiere country (O-02, TD-7).** Every term, the `s.52` reading and the PRO question depend on it.
8. **Her phone.** D-31 says Android. Which model and which browser or player, so the phone caption pass and the speaker sweep can be run on it by cable, and so the live-text caption fonts can be checked on it?
9. **Contacting the Sanidha project.** It needs an email; shall I treat it as out until after the premiere (my recommendation, secrecy)?
10. **Budget for the consult (O-04).** The T10 list now has eight music questions (E4).
11. **Which of the three Windows tests may I ask you to run first?** Template K item 2 takes about an hour; it is the gate for the settings card. Item 8 (the ten-minute A/B of `subtitles` against `ass`) is the quickest and the one that decides whether the captions can be burned with the project's SRT template at all.
12. **The bansuri custom.** The haveli page says her sampradaya's temple custom keeps the bansuri out as Krishna's emblem [88] (one maintenance-tagged page; UNVERIFIED; a 2026 paper's list of instruments of divine service includes Murali [97], so the custom is contested). Should the film's sound avoid a bansuri bed altogether unless a family source says it was hers?
13. **Which darshans and which songs does her home keep?** Any of the eight daily darshans (row N2), a morning prabhatiya, an aarti, a garba or women's festival songs, and from which book or edition: this fills Template N and the cue map without any guess from me.

### 6. Why Kumar One collapses under libass, and whether Hind Vadodara's missing digits are a Google Fonts packaging difference

**Answer: Kumar One's cause is found and reproduced: a defective TrueType `prep`/`maxp` pair that makes FreeType's hinted load fail, in the Google Fonts and the foundry's own builds alike. Hind Vadodara's digits were never drawn: not a packaging difference.** Data: `research/devotional-sound-script-fixtures/kumar_one_and_hind_vadodara_followup_2026-10-19.csv`; independently, [R9] reports "its TrueType hinting program fails in FreeType (new: an unhinted copy renders)", which this pins to a table.

- **Kumar One, the symptom.** Through libass 0.17.1 (ffmpeg 6.1.1 `ass`, FreeType 2.13.2, HarfBuzz 8.3.0) a 30-code-point test line of non-sacred syllables and a numeral at 86 px has 61 px of ink; the repaired copies below draw it at 542 to 544 px [108].
- **The cause, by ablation.** FreeType 2.13.2 alone (freetype-py, no libass, no HarfBuzz) fails a hinted load of every glyph tried with "execution context too long"; no-hinting, light and autohint loads succeed. The font has `fpgm` (265 bytes), `prep` (127 bytes) and `cvt `, but its `maxp` declares maxStorage 0, maxStackElements 0, maxTwilightPoints 0 and maxSizeOfInstructions 0, and no glyph carries instructions; the `prep` program loops on storage reads and writes. Deleting `prep` alone cures it (542 px), deleting all hinting tables cures it (544 px), and changing only `maxp` (maxStackElements 64, maxStorage 16, maxFunctionDefs 8, maxTwilightPoints 16) cures it (542 px); deleting `fpgm` alone or `gasp` alone does not. My reading: the loop never reaches its exit when the storage area has no slots and FreeType's runaway guard fires (inference from the disassembly and the error code).
- **Not a Google Fonts packaging difference.** The foundry's own `products/KumarOne-Regular.ttf` (847 glyphs, version string "PS 1.000") has the same `maxp`, `fpgm` and `prep` and collapses identically; the Google Fonts file (868 glyphs, "PS 1.001") is a later build with the same defect [108].
- **Not a libass-version matter, as far as tested.** libass only calls FreeType, so a newer libass (the changelog heading is 0.17.5 [76]) is not the lever; I could not build one and FreeType releases other than 2.13.2, the Windows build, Chromium and Android are untested (UNVERIFIED). The maker's debug log prints `Raster: FreeType x.y.z`; record it with the A/B.
- **Rule.** Kumar One is title art only: shape once, convert to outlines (T-10 item 2), so no renderer's hinting ever touches it. It is never a libass caption face. A repaired private copy is possible under OFL 1.1 (the font table records no Reserved Font Name for it [73]) but is unnecessary if the art is outlined.
- **Hind Vadodara.** The Google Fonts file has none of U+0AE6 to U+0AEF in its cmap. The foundry's `GlyphOrderAndAliasDB` lists gjZero to gjNine (977 names, 138 of them not in the 851-glyph binary), but its Glyphs source `masters/HindVadodara.glyphs` (515 glyph blocks) contains no glyph named gjZero to gjNine and no Unicode entry for 0AE6 to 0AEF, and the repository has no releases and no prebuilt font [109]. So the digits were never drawn; a foundry binary distributed elsewhere is UNVERIFIED. The rule stands: not for dates or years.
