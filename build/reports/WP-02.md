## 4. Deviations from the plan, with the reason

1. **`hours_bad_note.csv` is built by `tests/ops/make_fixtures.py`, not committed.** It holds a planted e-mail-shaped string, a profile path, an IP number and a handle; the repository is public and `public_lint.py` must stay clean (WP-03 builds its own bad strings from fragments for the same reason). The file is git-ignored (`tests/ops/fixtures/.gitignore`), the strings are joined from fragments, `run_tests.sh` builds it inside the test and deletes it afterwards. **The literal acceptance line needs the fixture first:** `python3 -I tests/ops/make_fixtures.py && python3 -I scripts/ops_lint.py --hours tests/ops/fixtures/hours_bad_note.csv; python3 -I tests/ops/make_fixtures.py --clean`. Without the file the tool says so and exits 2. The "name from a test deny list" is a made-up token in `hours_bad_note.deny.txt`; `ops_lint --hours FILE` reads a sidecar `FILE`-base `.deny.txt` as an extra deny list so the plan's command works without extra flags.
2. **Exit code on identifying data is 1, not 2.** Build plan 4.3 says identifying data found is exit 2, but the acceptance line for `hours_bad_note.csv` says exit 1; I followed the acceptance line. Exit 2 is used for a missing or invalid pattern file and for bad usage.
3. **The unfinished-work marker check is a plain string check.** Plan item 5 says "e-mail, IP, handle or TODO, all taken from the 4.13 pattern file", but 4.13 has no such category. The markers (the two words, built from parts in the source) are matched literally; every identifying-data category still comes from the file. If WP-03 adds a category for it, `ops_lint` runs it automatically with the others.
4. **`who` is limited to `maker` or `agent`** in both `hours_report.py` and `ops_lint.py` (Fable round-2 nudge 3, which post-dates the plan text). Only `maker` rows count towards H.
5. **The repository owner's account name is not copied into `decisions.csv`.** It appears in `DECISIONS.md` (D-14, D-26, O-13) and `CHARTER.md`. The generator writes `<owner>` instead (D-26: no usernames in generated files); `--check` applies the same rule, so the register stays untouched. **Orchestrator decision:** scrub the name from the register and charter too, or accept it as the public repository URL.
6. **D-14 is `superseded` through a one-entry table in the generator** (`KNOWN_SUPERSEDED = {D-14: D-26}`, conflict C-07) because the register text does not say so itself; D-23 is detected from the register ("superseded by D-29" in its title and "Replaces D-23" in D-29). Delete the table entry once the register states it.
7. **Extras not in the plan:** `ops/README.md`; per-table counts in the generator output; `since <date>` in the `note` of D rows (so the Table 1 "Since" column is not lost); the card's `Colour` row as its own row; a cross-check of the card's tested-script claim against `pipeline/phone/test_strings.json` when that file exists (otherwise a note says it was not cross-checked); `pipeline/phone/` is WP-04's, so it is only read.
8. **Mechanism tests use a synthetic mini pattern file when the real one is absent**, so the comparison, exit-code, masking and deny-list tests do not wait for WP-03; they say so in their evidence. Only tests of what counts as identifying data need the real file (the 5 BLOCKED).
9. **Language-and-script line.** It is exactly the planned text, with `<date>` for the orchestrator to fill from `PHONE-ROW.md`; I added a status paragraph under it saying the Devanagari test has not run yet. `ops_lint` refuses `signed: yes` while `<date>` is still there.
