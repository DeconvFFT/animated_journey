How the runner behaves (all of it tested, section 3):
- Sequential, in the fixed order `hygiene, win, ops, validators, render, roundtrip, sp1, win_lj, win_kit2, phone, spikes, runner, integration`. Each area runs as `bash tests/<area>/run_tests.sh --quick|--all` from the repo root, in its own session (`setsid`), stdin from `/dev/null`.
- `PASS` (exit 0), `FAIL` (non-zero; exit 3 gets the note "environment"), `TIMEOUT` (default 60 s for `--quick`, 900 s for `--all`, `--timeout N` overrides; TERM, then KILL after a 3 s grace, to the whole process group, so a child that ignores TERM dies too), `NOT LANDED` (no `run_tests.sh`; listed, never a failure). Runner exit: 0 / 1 (any FAIL or TIMEOUT) / 2 (usage, redaction) / 3 (environment).
- A process an area leaves behind after exiting is killed and named in the output (after a 1.5 s grace for ordinary exits).
- Evidence: for each entry it reads every `*.json` and `*.jsonl` under `build/evidence/wpNN/`, keeps the objects with `schema: lj-evidence/1`, de-duplicates by (package, test) with the newest `date_utc`/mtime winning, and counts PASS/FAIL/UNVERIFIED/SKIPPED/BLOCKED; the **lowest `disk.avail_mb_min`** over all its envelopes is shown, marked `LOW` below the 250 MB hard floor. A **Refreshed** column says whether any envelope was written during this run (an area whose `--quick` writes only a text log shows `no`, so older counts are not mistaken for this run). A `Check:` line is added where the exit code and the envelopes disagree (area exited 0 but FAIL envelopes are on file, or it failed but no FAIL/BLOCKED envelope exists).
- Redaction (D-26): everything stored or printed from an area passes through a masker that loads `Patterns` from `scripts/public_lint.py` and the categories of `scripts/redaction_patterns.json`; this file carries no regex of its own. A hit becomes its first two characters plus asterisks; control characters and colour codes are stripped. The scanner is proven live before anything runs (it must flag an e-mail-shaped sample built at run time) and the runner exits 2 without running anything if the pattern file or scanner is missing, invalid or dead. The three finished texts are masked once more, then (once it exists) fed to `public_lint.py --text`.
- Outputs are written beside the target and renamed. A run that stops after the areas started removes the older `INDEX.md`/JSON/`wave1_quick.txt` so a stale copy never looks current. One runner per evidence folder at a time (lock in the scratch folder).

## 2. How to run (exact commands, from the repository root)

```bash
bash scripts/run_week2_checks.sh --list            # the 13 areas in order and which have landed; writes nothing
bash scripts/run_week2_checks.sh --quick           # each landed area's run_tests.sh --quick; writes INDEX.md, week2_summary.json, wave1_quick.txt
bash scripts/run_week2_checks.sh --all             # each landed area's run_tests.sh --all (900 s each); writes INDEX.md, week2_summary.json, wp11a/console_all.txt
bash scripts/run_week2_checks.sh --quick --timeout 90
bash scripts/cleanup_scratch.sh                    # dry run (default): what would go, with sizes
bash scripts/cleanup_scratch.sh --yes              # delete the listed items; prints df before and after (end of the fortnight, not before)
bash tests/runner/run_tests.sh --quick             # about 32 s
bash tests/runner/run_tests.sh --all               # about 35 s
bash tests/runner/acceptance_transcript.sh         # about 4 min; rewrites build/evidence/wp11a/acceptance_transcript.txt and runs the real --quick
```

## 5. Deviations from the plan, with reasons

1. **`public_lint.py --text` is not used yet** (it does not exist). Instead the runner masks with `Patterns` from `public_lint.py` plus `redaction_patterns.json` (no regex of its own) and keeps the `--text` call as a second, fail-closed gate for when it lands.
2. **`--all` timeout 900 s per area** (the plan fixes only the 60 s `--quick` limit), plus a `--timeout N` option. A quick budget of 300 s is checked and reported (`OVER BUDGET` in `INDEX.md` and `over_budget` in the JSON) but does **not** change the exit code, so a slow shared machine cannot turn a green set red.
3. **Additions beyond the plan**, all small: `Refreshed` column and `Check:` lines in `INDEX.md` (so stale or contradicting evidence is visible), the single-runner lock, the stray-process kill, the 16 MB output cap, the abort-removes-stale-outputs rule, and the test hooks. None changes a planned behaviour.
4. **`cleanup_scratch.sh` has more safety than the plan lists**: the scratch folder's name must contain "scratch", must be outside the repo and at least two levels deep, links are skipped never followed, and `--yes` takes `<scratch>/disk.lock` without waiting (BUSY, exit 3) so it cannot pull a download or render out from under a guarded job. The plan's refusals (`/`, `$HOME`, anything outside `<scratch>`, `vendor/`, `renders/`) are all there.
5. **The `Owner` column reads `sonnet-implementor (tests/<area>/)`**: the plan says "owner" without defining it; this names the implementing agent and the folder to look in. The entry (WP-id) is its own column.
6. **`wp11a/summary.json` exists only after `--all`** (`summary_quick.json` and `summary_all.json` always), so a quick run never overwrites the full result that `INDEX.md` links.
7. **Counts in `INDEX.md` are "latest envelope per test on file", not "this run only"**; the `Refreshed` column says which. The plan did not say; counting only this run would show zeros for every area whose `--quick` writes only a text log.

## 7. Notes for the other packages

- A package's `run_tests.sh --quick` should finish in well under 60 s and write `lj-evidence/1` envelopes **in `--quick` too** (JSON or JSONL under `build/evidence/wpNN/`), otherwise its `INDEX.md` row shows `Refreshed: no`. Exit non-zero on any FAIL; exit 3 for "environment".
- Do not call `run_week2_checks.sh` from inside a test on the real tree (refused with exit 3). To test the runner, use the hooks as `tests/runner` does.
- Output that an area prints is stored in `build/evidence/wp11a/area_<area>_<mode>.txt` after masking, last 400 lines. Keep names, hosts and personal paths out of test output anyway; masking is a net, not a licence.
