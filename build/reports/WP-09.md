- **D1. The self-test file carries a quiet test tone** (`--selftest` and `--test-tone`: 1 kHz, calibrated to -16.0 LUFS, true peak -15.3 dBTP, AAC-LC 48 kHz stereo from the chain's own audio args). - **D2. `pil_resize_box` is ported, not imported.** The reference has no import-time side effects, but its frame count `N` is a module constant and it only does a centred push; the tool needs a pan and a pull, any frame count, and a 16:9 window inside a non-16:9 still. The port cites the file in the header and a test proves identical pixels.
- **D3. The self-test always also makes the zoompan proof, and its lossless windows are 48 frames** (the maker's default is 96). A lossless 4:4:4 10-bit window is large: 231 MB for 96 frames of a high-contrast noise still in my first prototype, 17 MB for 48 frames of the final low-contrast neutral stills, an estimated 100 to 250 MB for real photographs. With the volume at 650 MB free the tests could not afford the large cases. `--gate-window` is off unless asked. The low-contrast stills leave a smaller margin than a real photograph would (MO8b 0.0162 against 0.04; the prototype with contrast read 0.005 to 0.01) and the zoompan variant still fails by a wide margin.
- **D4. `checksums.txt` covers `01_masters` only, with paths relative to it.** The reused `mk_manifest.ps1` hashes the folder it is run in; run at the archive root it would hash `manifest.csv` and `steps.csv`, which change whenever the maker adds a row. ## 7. Findings and requests for the orchestrator and other packages

1. **F-1 (cross-package, affects the maker's Monday).** `python -I` ignores the folder that `pip install --user` fills. I verified it here: a module in the user site is found by plain `python3` and not by `python3 -I` (`ENABLE_USER_SITE` is False). The plan's own install line is `py -3 -m pip install --user pillow numpy`, and every project tool is run `py -3 -I`.
