**What "pass" means for a listed path.** `rel` equals an entry's `path` as a string (no glob, no folder); and the file is a real PNG (8-byte signature and an `IHDR` chunk at offset 12) of fewer than 200,000 bytes ("200 KB" counted as 1,000 bytes, the way the project already counts "about 80 KB" for 80,413 bytes: 199,999 passes, 200,000 fails). It is judged **twice**, on the copy in the git index (what a commit takes) and on the working-tree copy (what `git commit -a` would take); both must pass when both exist. The list itself must be valid or every force-add fails: a glob or pattern character, a folder, an absolute or `..` path, a non-`.png` path, a duplicate, a missing `reason` or `review` all make it invalid; `run_all_checks.sh` and the integration test also require the cited `review` to be a file in the repository (the lint does not, so a scratch `--root` without the review still lints).

The maker's PC runs `public_lint.py` through `lj.ps1 close` with `py -3 -I`; a Windows run of the lint on a force-added card is UNVERIFIED. The underscore integer literal needs Python 3.6 or later.
3. **The list pins a path, not bytes.** A different PNG under 200 KB put at the same path and force-added would pass; the safeguard is the review of the diff, as with the `allow_binary` glob. A `sha256` per entry would pin the bytes, but a rebuild of the cards with another Pillow (the fixture README says the same Pillow gives the same bytes) would then need a config edit. Not done; your call.
4. **PNG means signature and `IHDR`, not a full decode.** A file with those 16 bytes and anything after passes. Metadata chunks are not inspected.
