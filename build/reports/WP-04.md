## 2. How to run it (exact commands)

```bash
export PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers                  # never "playwright install"
bash pipeline/lib/fetch_libs.sh                                   # exit 0, or 3 with the exact npm error; --check verifies offline
node pipeline/bin/render.mjs --dir pipeline --page scenes/testcard/scene.html --mount /vendor=vendor \
     --out renders/wp04/a --seconds 2 --json renders/wp04/a.json  # 48 PNG frames and a report
node pipeline/bin/render.mjs --dir pipeline --page scenes/testcard/scene.html --mount /vendor=vendor \
     --seconds 2 --chain h264 --ffmpeg renders/wp04/a.mp4          # piped into ffmpeg, no PNGs
bash tests/render/run_tests.sh --quick                            # about 30 s
bash tests/render/run_tests.sh --all                              # about 15 minutes with the waits; timed runs under lj_bench
bash spikes/sp2_route_a/run_sp2.sh                                # --all, then results.json
```

`render.mjs` options: `--page --dir --mount (repeatable) --out --fps (24) --w --h (1920 1080) --seconds | --frames A:B --shard i/n --concurrency N --alpha --chain NAME --ffmpeg|--video OUT --encode --json FILE --max-seconds S --fail-on-pageerror --overwrite --ready-timeout --frame-timeout --serve --serve-seconds --chains-file --ffmpeg-bin --list-chains --quiet --help`. Exit codes: 0 done (also the soft cap); 1 the encoded file does not match the chain; 2 bad usage or a broken scene (network request, `seekTo` threw, 404 on a local file, never ready, uncaught page error); 3 environment (no Playwright, Chromium or ffmpeg; time cap in video mode); 130/143 signal. On exit 2 or 3 the output of that run is removed.

## 4. What the work found (details in `VERDICT-SP2.md`)

1. **Frames depended on history.** With R7's flags a flat SVG scene differed between 1 page and 4 pages in 58 to 64 of 96 frames, and a resumed run did not equal an uninterrupted one. `--disable-partial-raster --disable-gpu-compositing` removes it and is about 50% faster. They are the harness defaults. **For `research/agent-pipeline.md` R7 and the pipeline skill (WP-11b stages them):** "identical per machine" holds only with these flags, and the R7 code block has none of the changes listed in section 5.
2. **The MO8 gate needs a measurable texture.** Random speckle, dense hatch and converging lines read 0.04 to 0.12 px for a perfect push; posterised smooth noise plus a few hairlines reads 0.002 to 0.004 px. The gate's frame set is `?view=detail`.
3. **`document.fonts.check` alone proves little**; A7 uses blocked-vs-loaded ink with bounding-box-aligned masks (unaligned IoU of the control was 0.50, aligned 1.00).
4. **F-09 was a real leak**, now tested with a control.
5. **Resume needs a scene fingerprint**, otherwise "skip frames that exist" mixes scenes silently.
6. **Disk:** the volume ran between 192 and 421 MB free during this work and was below the guard's 250 MB hard floor for minutes without any write of mine (my largest footprint at any time was about 30 MB; a SIGKILL test also leaks about 2 MB of Chromium temp profile in `/tmp`, which the test now removes).

## 5. Deviations from the plan, with reasons

* **More Chromium flags than the plan lists:** `--disable-partial-raster`, `--disable-gpu-compositing` (the finding above), `--force-color-profile=srgb` (my addition for exact patches; not tested without it), `--disable-renderer-backgrounding --disable-background-timer-throttling --disable-backgrounding-occluded-windows`, `--no-proxy-server`, and a host-resolver rule that resolves only loopback (belt and braces for network off). All are listed in every report; `PW_EXTRA_FLAGS` and `PW_DROP_FLAGS` exist for experiments.
* **`--chain h264`** resolves to `h264_venue` in `chains.json` when the file is present (WP-05 landed during the work); the built-in `h264` is an equal copy used only when the file is absent, and `chain_parity` asserts equality. `expect_extra` is merged into `expect` and the encoded file is probed against it (exit 1 on a mismatch).
* **Texture:** the plan says "seeded-LCG fine-detail panel". It is seeded-LCG, but posterised smooth noise plus 600 crisp hairlines and dots rather than random speckle, because speckle made the MO8 gate fail a perfect push (finding 2).
* **A4 on `flat.html`**, A1 to A3 on the test card, to keep the disk write small (the card is 314 KB a frame).
* **A6 (f):** planned MB recomputed (12, not 250) after the guard refused 250, then still refused; a RAM-output fallback test was added. The guarded stage stays BLOCKED, not marked passed.
* **A7:** IoU on bounding-box-aligned masks (raw IoU recorded too); N is defined as the number of differing ink pixels the 0.8 threshold implies for that string's own union (`ceil(0.2 x union)`), measured in the same run.
* **`test_strings.json`:** the Latin entry also carries `checked_by_reader: false` (4.10 says every entry carries it; the 4.15 example omits it). Everything else is as 4.15.
* **Added beyond the plan** (inside my owner paths): `--encode`, `--serve`, `--video`, `--overwrite`, `--list-chains`, `window.ljReport()`, the scene fingerprint guard, `flat.html`, `fonts.html`, `smoke3d.html`, and the tests marked "extra" above. A11 was run here as soon as WP-05 landed instead of waiting for WP-11b.
* **Fonts from `fontsource` npm packages** (as the plan says); the `.woff` file of the 400 weight in the script's own subset is fetched too, because Pillow-raqm cannot read `.woff2` (the A7 reference). The GSAP package ships no licence file, so `licences/gsap-LICENSE.txt` is a record I composed from the vendor page (read 2026-10-19) and the package metadata.
* **`fetch_libs.sh`** is a bash wrapper around an embedded `python3 -I` program (JSON and hashing), run from a new empty folder in the scratch area with a throw-away npm cache; `npm view` is also used to confirm the pending package names.
