## 5. Deviations from the plan, with reasons

- **D-1 Guard test numbers.** The plan says a fake df of 700 MB: "planned 350 runs, planned 320 exits 3". By its own rule (`Avail - planned >= 400`) 350 leaves 350 and is refused while 320 leaves 380 and is also refused. I implemented the rule and tested the consistent numbers: 300 runs (boundary), 301, 320 and 350 are refused with the exact figures.
- **D-2 Additions to the frozen pattern file (all additive, all with positive and negative samples; verified against both existing consumers).** Exemptions: `reserved_example_email_domains` (example.com/.org/.net, `.invalid`, `.test`), `url_embedded_ids` (a GUID or hex id inside a web address is a citation), `known_non_serial_tokens` (SHA256SUMS, ProRes profile names, PubMed ids), `at_words_not_handles` (at-rules and tags). Extra keys: `mask.cap`, `placeholder_aliases`, `path_denylist_exempt_dirs`, `apply_to` on `handle`, top-level `samples[]` (cross-cutting samples with a `file_kind`), more version fields. IPv6 compressed forms need 3 to 7 explicit groups (so `Add::add`, a loopback or a link-local suffix are not hits); a Windows profile path also matches `/mnt/c/Users/...`. Without these the real tree gave hundreds of false hits (SHA256SUMS alone: 87).
- **D-3 Public-lint config, not the frozen file, holds the tool-specific relaxations:** `denylist_exempt_globs: **/*.schema.json` (see finding F-5), an `allow` list (on the last whole-tree run it suppressed 107 four-part software-version hits in research notes, 11 git commit ids, 3 hits of one Store product id and 4 verbatim licence-text contact lines), `allow_binary` for two synthetic fixtures, fixture folder demotes only `guid_serial` to a NOTE, and in markdown an at sign inside inline code or a fence is not a handle. The allow list is short and deliberately excludes e-mail addresses, creator handles and session ids.
- **D-4 Exit codes of `public_lint.py`:** 2 for identifying data (4.3), 1 for hygiene and theme findings, so a caller can tell them apart.
- **D-5 `stale_check.py`:** `--strict` and report mode both exit 1 on a non-allowlisted FAIL; strict prints only those lines. `ops/decisions.csv` is excluded (it is the generated mirror of the register and quotes every stale value by design; the plan lists `ops/` whole). - **D-6 Allowlist contexts are the W-29 list, written as regexes** that cover the wording variants actually present (`there are no insiders`, `Ring 1 (...) and Ring 2 (...) are empty`, a `tested at 25 ... UNVERIFIED at 24` comment up to 3 lines above a command, `50 Hz ... judder ... access copy`). No other entry exists.
