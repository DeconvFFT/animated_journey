## 2. How to run (from the repository root)

```bash
bash tests/sp1/run_tests.sh --quick        # about 10 s, no downloads
bash tests/sp1/run_tests.sh --all          # about 5 min: real network lines (six small files, one wrong asset; the real EffectCraft stage is reused from the ledger, not downloaded again) + the stand-in mechanism tests
bash spikes/sp1_craft_cli/run_sp1.sh --list                                 # plan, sizes, df, profile; exit 3 if Avail minus planned is under 400 MB
bash spikes/sp1_craft_cli/run_sp1.sh --sums-only                            # six SHA256SUMS.txt + 12 HEAD requests -> release_assets.json
bash spikes/sp1_craft_cli/run_sp1.sh --only effectcraft v0.11.1 --t1-only   # one real download, T1, everything deleted
nohup bash spikes/sp1_craft_cli/run_sp1.sh --all --profile full > /dev/null 2>&1 &   # the real staged run (hours): FilmCraft (kept tarball reused), then EffectCraft (second fetch, recorded exception)
python3 -I spikes/sp1_craft_cli/drivers/verdict.py                          # rewrite VERDICT-SP1A.md from the evidence
python3 -I spikes/sp1_craft_cli/build_guide.py && python3 -I spikes/sp1_craft_cli/check_guide.py
```

Exit codes follow 4.3: 0 all pass; 1 a test failed or a hash did not match; 2 bad usage, or (drivers) the harness could not drive the CLI; 3 environment (disk guard refused or tripped, lock busy, download blocked). One internal code is added between a stage and `--all`: 4 = the tarball was rejected by its SHA-256 (stop and report); `run_sp1.sh` itself never exits 4, it exits 1 (documented in the script header).

What they cannot prove: the real parameter names, the real output shapes (clip ids, `offlineMedia`), the real memory and speed.

With 1.1 GB the full profile fits and Q-1 is not needed for this package. Q-2 (who else writes here) is the cause and still stands. Anything that commits to this repo needs a few MB too.

The first real run records the true figure (`avail_drop_mb` in the stage envelope, flagged if more than 25% over plan); WP-10's estimates can then be tightened. PhotoCraft, VectorCraft and LightCraft have no independent value (integrity only, said in the file).

7. **A guard-stopped stage could be cut short by a second TERM** (the guard's group signal plus `timeout`'s forward). Found by the test `fake.disk_floor_abort_cleans_up` (run 2: leftovers), fixed (the first TERM makes the trap ignore further ones), and the same test passes in the final run.
