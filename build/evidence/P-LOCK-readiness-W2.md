*Written Mon 19 Oct 2026 by the WP-11b implementor (branch `build/process-lock`). For Fable's Fri 30 Oct read and as the input to the Sun 8 Nov mid-point check. Nothing here is signed or approved by an agent; nothing counts as done until `fable-advisor` approves it.*

**How to read it.** Every row has exactly one status from this list, and the status is the *binding* one: the weakest link between today and a P-LOCK pass.

| Status | Means |
|---|---|
| `PASS (container)` | the whole pass condition is met by evidence made in the cloud container, and no Windows behaviour is part of it |
| `UNVERIFIED (Windows)` | the container evidence is complete; what remains is a Windows behaviour nobody has observed yet |
| `maker-owed (date)` | a person, the maker, must act on that date before the item can pass (the container part may be finished) |
| `not started (week N)` | no work product exists that could pass it, or its real run has not been done |

**The rule that is never broken: nothing that needs Windows reads PASS.** The "Needs Windows" column says which rows these are; a test (`readiness.map_statuses_and_evidence`) fails if one of them reads PASS, if any row has no status, or if `lj.ps1 close` reads anything but "not started" with the sentence below. Every Linux result for a Craft app is a **Linux CLI result and not evidence for Windows**. A "container-side proof" in a row says what the agents showed; it never upgrades the status.
